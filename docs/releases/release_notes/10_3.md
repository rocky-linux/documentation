## Rocky Linux 10.3

Rocky Linux 10.3 (RL 10.3) is the latest minor release of Rocky Linux's enterprise operating system. Listed in this document are the **most notable** changes between 10.2 and 10.3. If something is not listed, it probably means it has changed little since 10.2. If you are migrating to Rocky Linux 10 for the first time, you might want to review the release notes for [10.0](10_0.md), [10.1](10_1.md) and [10.2](10.2.md) as well. These earlier versions still contain some key or important annotations.

### Upgrading to Rocky Linux 10.3

To upgrade from any version of RL 10 to 10.3, simply run `dnf -y upgrade`.

Rocky Linux does not support upgrading across major versions. To move from 8.x or 9.x to Rocky Linux 10.x, perform a fresh install of the operating system and restore data from a backup.

### New Features and Changes

The following sections describe selected features of RL 10.3.

As with all Rocky Linux releases, this release note covers numerous enhancements, changes, and new features.

For a complete list of major changes, see the upstream listing [here](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/10/html/10.2_release_notes/overview).

### Supported Architectures

!!! warning "Please check CPU Compatibility"

    On the x86_64 processor architecture, RL 10 no longer supports hardware at the x86-64-v2 microarchitecture level and earlier, and makes the x86-64-v3 microarchitecture level the baseline for distribution. To test your CPU's microarchitecture compatibility, [use this procedure](../../gemstones/test_cpu_compat.md).

### Infrastructure services

- RDMA support is now available for Valkey

### Kernel

- rebases the eBPF and `perf` tool to upstream version 6.19
- extends `rtla` with custom eBPF threshold-overflow actions, and clearer `timerlat` stack analysis for EFI call paths
- tightens Integrity Measurement Architecture (IMA) appraisal on previously unevaluated file systems
- updates `tboot` for Trusted Execution Technology workflows
- expands Intel Resource Director Technology support through `intel-cmt-cat` rebase, with related QuickAssist Technology (QAT) and IAA userspace updates
- refreshes IBM Z tooling and crytography packages, including `libzpc` version 2 support
- continues memory-management and CXL-related enablement for Grace and special-purpose memory configurations
- enables AMD `amdxdna` driver for Neural Processing Units (NPUs) as a Technology Preview on AMD-based systems

### Security Features

- the rebasing of Keylime to version 7.14 and `keylime-agent-rust` to 0.2.10, adding support for agent-driven push attestation in edge and NAT environments and evidence verification for AMD SEV-SNP confidential virtual machines
- contains the `fapolicyd` framework in version 2.0.1, which introduces multi-threaded parallel decision processes, transactional policy and trust database updates, dynamic database sizing, and `systemd` watchdog integration
- the rebasing of the `libreswan` packages to version 5.4, adding support for ML-KEM-768 and ML-KEM-1024 post-quantum key exchange algorithms in IKEv2 and multiple key exchanges according to RFC 9370
- the `rust-sequoia-sqv` package 1.5.0 provides full support for PQC based on the final OpenPGP RFC 9980
- the rebasing of the `audit` packages to 4.2.1 introduces support for TLS 1.3 with post-quantum crytography (PQC) and PSK authentication for remote logging, as well as `cgroup` and `cgroup2` filesystem filtering in `auditctl`
- the support and preference for `mlkem768nistp256-sha256` and `mlkem1024nistp384-sha384` hybrid post-quantum key exchange algorithms for SSH connections in FIPS mode
- the `crypto-policies` packages introduces the `NO-HMAC-SHA1` subpolicy for disabling SHA-1 in HMAC operations to satisfy security compliance scanner requirements
- the updating of the OpenSC tools and middleware to version 0.27.1, introduces support for PKCS #11 version 3.2 specifications and post-quantum cryptography features
- the `aide` package now includes a pre-configured `aide-check.timer` `systemd` timer unit for automated integrity checks, and supports modular drop-in configuration files in the `/etc/aide.d` directory
- the rebasing of the `libcap-ng` package to version 0.9.3, provides the new `cap-audit` tool to inspect application capability requirements and an advanced attack surface inspection option in `netcap`
